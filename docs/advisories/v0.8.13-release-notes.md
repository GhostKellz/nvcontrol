# v0.8.13 driver support update

This release adds native vibrance support for the NVIDIA 615 allocation ABI,
retains the existing older-driver allocation paths, and extends runtime feature
reporting. The driver and proprietary userland must already match; nvcontrol
does not replace them during an application update.


The driver also removes `NVKMS_IOCTL_CHECK_LUT_NOTIFIER`. Commands after that
entry shift down by one: set/get/valid-values display attributes use 21/22/23,
while the retained branches use 22/23/24. The ioctl dispatch helper selects the
command map from the loaded module independently of allocation-size fallback.
The removed command is rejected instead of accidentally dispatching its successor.

## Independent review

C probes against the local tagged NVIDIA headers confirmed allocation sizes of
1440 bytes for 610 and 1448 for 615. The reply fields read by nvcontrol have the
same offsets. GetDpyAttribute parameters are 24 bytes on both releases, correcting
the earlier readiness outline's 32-byte claim. SetDpyAttribute remains 32 bytes.

The previous binary reproduced `AllocDevice` failure on the live driver. The
implementation extends the existing named constants and branch ordering rather
than replacing the controller or changing device permissions.

## Features and packaging

- Detect low-latency revision 2 and cluster acceleration from Vulkan output.
- Report driver support for memory partitioning, expanded color-depth reporting,
  the optional display-clock override, and effective suspend-notifier status.
- Preserve the merged dependency update and synchronize Flatpak offline sources.
- Synchronize Cargo, Arch, Debian, Fedora, AppImage, Flatpak, and manual metadata.
- Keep older driver guidance and the legacy 590 path explicit.

## Diagnostic portability follow-up

Package ownership uses the host database. Optional module parameters need not
appear on the boot command line. DKMS selects the registered module/version,
keeps working registrations during repair, reports build failures, and recognizes
distro-owned kernel hooks. Initramfs names follow mkinitcpio, dracut or
update-initramfs conventions. See [DKMS](../drivers/dkms.md) and the
[testing methodology](../testing/methodology.md) for scope and pending coverage.
